서버 아키텍처 방식, 어떤 구조로 갈까요?

3가지 방식 중 하나를 골라주세요. 각 방식의 복잡도와 유연성이 달라요.

A

⚡ Flutter → Supabase 직접 연결

앱에서 Supabase SDK를 직접 호출. 별도 서버 없음.

Flutter 앱 ──────────────▶ Supabase
Auth · Database · Storage 직접 접근
✓ 가장 단순 ✓ 초보자 최적 ✓ 빠른 개발 ✗ 복잡한 로직 한계
B

🔧 Flutter → Supabase + Edge Functions

기본은 직접 연결, 복잡한 로직(금리 수집, AI 호출)만 Supabase 내부 함수로 처리.

Flutter 앱 ───▶
Supabase DB + Edge Functions
금리수집 · AI조언 · 공유링크 생성
✓ 균형 잡힌 구조 ✓ 서버 관리 불필요 ✓ 4단계 AI까지 확장 가능 △ A보다 약간 복잡
C

🏗️ Flutter → 별도 백엔드 서버 → Supabase

Node.js 또는 Python 서버를 별도로 운영. 앱은 이 서버를 통해서만 데이터 접근.

Flutter ▶ 백엔드 API ▶ Supabase
완전한 제어권, 서버 직접 운영 필요
✓ 최대 유연성 ✗ 서버 운영 비용 발생 ✗ 초보자에게 과도한 복잡도

⭐ 추천: B (Supabase + Edge Functions). 1단계는 A처럼 단순하게 시작하고, 2~4단계에서 Edge Functions를 추가하는 방식이에요. 별도 서버 없이도 AI까지 구현 가능해요.
