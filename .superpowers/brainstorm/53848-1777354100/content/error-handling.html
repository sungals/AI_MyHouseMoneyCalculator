섹션 4: 오류 처리

서버와 연동하면 네트워크 오류, 인증 오류 등이 생길 수 있어요. 각 상황별로 어떻게 대응할지 정의해요.

📡 오프라인 / 네트워크 없음 투명하게 처리
상황
인터넷 연결 없이 앱 사용 시도
처리 방식
• Hive 로컬 데이터로 정상 작동
• 상단에 오프라인 모드 배지 표시
• 온라인 복귀 시 자동 동기화
⚡ 동기화 충돌 서버 우선 전략
상황
오프라인 중 수정한 데이터와 서버 데이터가 다를 때
처리 방식 (1단계)
• 서버 데이터 우선 (가장 단순한 전략)
• created_at 타임스탬프로 최신 항목 유지
복잡한 머지 로직은 2단계 이후에 고려
🔐 인증 오류 (세션 만료) 재로그인 유도
상황
JWT 토큰 만료 또는 비정상 세션
처리 방식
• Supabase SDK가 자동 토큰 갱신 시도
• 갱신 실패 시 로그인 화면으로 이동
• 로컬 데이터는 그대로 유지 (데이터 손실 없음)
🌐 서버 오류 (5xx) 사용자 친화 메시지
상황
Supabase 또는 Edge Function 오류
처리 방식
• 토스트 메시지: "잠시 후 다시 시도해주세요"
• 로컬 작업은 계속 가능
• 개발 중엔 콘솔에 상세 오류 로그
💡 핵심 원칙: 오류가 나도 앱이 멈추면 안 돼요

서버 연동 코드는 항상 try/catch로 감싸고, 실패해도 로컬 기능은 유지되도록 설계합니다. 사용자는 "서버가 잠깐 느릴 수 있다" 정도만 알면 충분해요.
