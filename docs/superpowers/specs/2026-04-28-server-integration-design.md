## 개요

Flutter로 만든 주택 자금 계산기 앱을 Supabase 서버와 연동하여 4단계에 걸쳐 확장한다. 서버 초보자도 단계별로 진행할 수 있도록 1단계(클라우드 동기화)를 기반으로 이후 단계를 쌓아가는 구조다.

### 4단계 로드맵

| 단계 | 기능 | 난이도 |
|------|------|--------|
| 1 | 클라우드 동기화 — 로그인, 히스토리 저장 | 초급 |
| 2 | 실시간 금융 데이터 — 한국은행 API 금리 자동 반영 | 중급 |
| 3 | 공유 / 커뮤니티 — 결과 링크 공유, 지역 시세 | 중급 |
| 4 | AI 분석 — Claude API + 벡터 검색 기반 조언 | 고급 |

## 섹션 1: 전체 아키텍처

### 방식: Flutter → Supabase + Edge Functions

```
Flutter 앱
    │
    ├──── Supabase Auth (로그인/로그아웃)
    ├──── Supabase Database (PostgreSQL, 계산 히스토리)
    ├──── Supabase Realtime (오프라인 → 온라인 동기화)
    └──── Edge Functions (복잡한 로직: 금리 수집, AI 호출, 공유 링크)
```

- **1단계**: Flutter ↔ Supabase 직접 연결 (Auth + DB)
- **2~4단계**: 필요한 로직만 Edge Function으로 추가 (Deno/TypeScript)
- 별도 백엔드 서버 없음, 서버 관리 비용 없음

### 플랫폼 선택: Supabase

- PostgreSQL — SQL 구조로 복잡한 쿼리 지원
- 4단계 AI에 필요한 벡터 검색(pgvector) 내장
- 대시보드에서 테이블 뷰로 데이터 직접 확인 가능
- 무료 플랜: 프로젝트 2개, DB 500MB

## 섹션 2: 데이터 모델

### users 테이블 (Supabase Auth 자동 생성)

| 컬럼 | 타입 | 설명 |
|------|------|------|
| id | uuid | Supabase Auth UID (PK) |
| email | text | 이메일 |
| created_at | timestamptz | 가입일 |

### calculation_history 테이블

| 컬럼 | 타입 | 설명 |
|------|------|------|
| id | uuid | PK (자동 생성) |
| user_id | uuid | FK → auth.users.id |
| feature_type | text | 'rent_compare' \| 'semi_rent' \| 'loan_interest' \| 'monthly_expense' \| 'tax_deduction' |
| input_data | jsonb | 계산 입력값 (기능별 구조 다름) |
| result_data | jsonb | 계산 결과값 |
| created_at | timestamptz | 계산 시각 (ISO 8601, UTC) |
| synced_at | timestamptz | 서버 동기화 시각, null = 미동기화 |

**Row Level Security (RLS)**: `user_id = auth.uid()` — 본인 데이터만 읽기/쓰기 가능

### 이중 저장 구조

```
계산 실행
    │
    ├── Hive (로컬) — 항상 즉시 저장
    └── Supabase (클라우드) — 온라인 시 동기화
         └── 오프라인 중 입력 → 온라인 복귀 시 일괄 업로드
```

기존 Hive 로직은 그대로 유지. Supabase는 레이어로 추가.

## 섹션 3: 인증 흐름

### 비회원 경로
1. 앱 실행 → "로그인 없이 시작" 선택
2. 모든 데이터 Hive 로컬에만 저장
3. 나중에 계정 연결 시 → Hive 데이터 자동 Supabase 이전

### 이메일 가입 경로
1. 이메일 + 비밀번호 입력
2. Supabase가 인증 메일 자동 발송
3. 링크 클릭 → 로그인 완료

### 최초 로그인 시 데이터 이전
- 기존 Hive 데이터를 Supabase로 일괄 업로드 (자동)
- 이후: Hive(로컬) + Supabase(클라우드) 이중 저장
- 오프라인에서도 모든 기능 정상 작동

### 인증 방식
- **1단계**: 이메일 + 비밀번호 (Supabase 기본 제공)
- **이후 추가 가능**: 구글 로그인 (OAuth 설정만 추가)

## 섹션 4: 오류 처리

| 상황 | 처리 방식 |
|------|----------|
| 오프라인 / 네트워크 없음 | Hive 로컬로 정상 작동, 상단 "오프라인 모드" 배지 표시. 온라인 복귀 시 자동 동기화 |
| 동기화 충돌 | 서버 데이터 우선 (created_at 타임스탬프 기준). 복잡한 머지는 2단계 이후 고려 |
| 인증 오류 (세션 만료) | Supabase SDK 자동 토큰 갱신 시도 → 실패 시 로그인 화면 이동. 로컬 데이터 유지 |
| 서버 오류 (5xx) | 사용자에게 토스트: "잠시 후 다시 시도해주세요". 로컬 기능 계속 작동 |

**핵심 원칙**: 모든 서버 연동 코드는 `try/catch`로 감싸고, 실패해도 로컬 기능은 반드시 유지.

## 섹션 5: 테스트 전략

### 1단계 완성 후 수동 체크리스트

- [ ] 이메일 회원가입 → 인증 메일 수신 → 로그인 성공
- [ ] 비회원으로 계산 저장 → 계정 연결 → Supabase 데이터 이전 확인
- [ ] 비행기 모드 → 계산 입력 → 와이파이 켜기 → 자동 동기화 확인
- [ ] 로그아웃 → 재로그인 → 히스토리 복원 확인
- [ ] Supabase 대시보드에서 저장된 데이터 직접 확인

### 단위 테스트 (기존 유지)
- 계산 로직(전월세 전환, 대출 이자 등)은 서버 무관하게 계속 테스트
- 서버 연동 추가 후에도 기존 테스트 통과 여부 확인

### 통합 테스트 (1단계 완성 후 추가)
- Supabase 테스트 프로젝트 별도 생성 (무료 플랜 활용)
- Flutter `integration_test` 패키지로 로그인 플로우, 저장/불러오기 자동화

### 권장 순서
수동 체크리스트 → 기존 단위 테스트 유지 → 통합 테스트 추가

- Supabase 프로젝트 생성 및 테이블 설정

- 로그인/로그아웃/비회원 화면 구현
- 기존 Hive 저장 로직에 Supabase 동기화 레이어 추가
- 오프라인 감지 및 재연결 시 동기화 처리
- 최초 로그인 시 Hive → Supabase 데이터 이전
